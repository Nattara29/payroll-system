# แผนพัฒนาระบบเงินเดือน เทศบาลเมืองศรีสัชนาลัย

อ้างอิงจาก 16 ความสามารถที่ต้องการทั้งหมด แบ่งเป็นเฟสที่ทำได้จริงทีละก้อน
เพื่อไม่ให้เรียนรู้/ทดสอบพร้อมกันเยอะเกินไป

## เฟส 0 — โครงสร้างพื้นฐาน (เสร็จแล้ว ✅)
- ตั้งฐานข้อมูล Supabase (ตาราง + Row Level Security)
- ระบบล็อกอิน/สมัครสมาชิก (Supabase Auth)
- โครงหน้าเว็บ (sidebar/topbar), ธีมสีเขียว
- แดชบอร์ดสรุปตัวเลขเบื้องต้น

## เฟส 1 — นำเข้าข้อมูลเงินเดือน (เสร็จแล้ว ✅)
ตรงกับข้อ 1–6 ในสิ่งที่ต้องการ:
1. Upload Excel เงินเดือน
2. ตรวจสอบข้อมูลก่อนบันทึก (ตรวจโครงสร้างไฟล์)
3. Mapping คอลัมน์ Excel กับข้อมูลในระบบ
4. ตรวจสอบข้อมูลผิดพลาด (รวมยอดไม่ตรง, ชื่อซ้ำ, ข้อมูลขาด)
5. ยืนยันการนำเข้า
6. เก็บข้อมูลเงินเดือนตามเดือน/ปี

พร้อมระบบจำแม่แบบ mapping ไว้ใช้ซ้ำเดือนถัดไป (`column_mapping_templates`)

## เฟส 2 — ค้นหา/ดูข้อมูล (เริ่มต้นแล้ว บางส่วน 🟡)
7. ค้นหาพนักงาน — ทำแล้ว (หน้า "บุคลากร")
8. ดูรายละเอียดเงินเดือน — ทำแบบพื้นฐานแล้ว (ปุ่ม "ดูประวัติเงินเดือน")
13. ดูประวัติการนำเข้า — ทำแล้ว (หน้า "ประวัติการนำเข้า")

**ยังต้องทำต่อ:** หน้าดูรายละเอียดเงินเดือนแบบสวยงาม (ไม่ใช่ alert popup),
กรองตามงวด/กอง/ประเภทพนักงาน

## เฟส 3 — สลิปเงินเดือน (เสร็จแล้วบางส่วน 🟡)
9. สร้างสลิปเงินเดือน — ทำแล้ว (หน้า "สลิปเงินเดือน": เลือกงวด+ค้นหาพนักงาน แสดงสลิปขนาด A4
   มีลายน้ำโลโก้จาง ๆ กลางหน้า, หัวกระดาษโลโก้+ข้อมูลหน่วยงาน, แสดงเฉพาะรายการที่มีจำนวนเงิน)
10. พิมพ์สลิป — ทำแล้ว (ปุ่ม "พิมพ์" ใช้ `window.print()` ตั้งค่า `@page` เป็น A4 แล้ว)
11. Export PDF (รายคน) — ทำแล้ว (ปุ่ม "ดาวน์โหลด PDF" ใช้ `vendor/html2pdf.bundle.min.js`)
12. Export PDF หลายคนพร้อมกัน — **ทำแล้ว ✅** ตารางค้นหาสลิปมีช่องติ๊กเลือกหลายคน + "เลือกทั้งหมด"
    ปุ่ม "ดูตัวอย่าง/พิมพ์-ดาวน์โหลดที่เลือก" จะต่อสลิปทุกคนที่เลือกเป็นหลายหน้าในตัวอย่างเดียว
    ปุ่ม "พิมพ์" เดิมใช้ได้ทันที (แต่ละคนขึ้นหน้ากระดาษใหม่ด้วย CSS page-break) ปุ่ม "ดาวน์โหลด PDF"
    เดิมก็ใช้ได้ทันทีเช่นกัน จะรวมเป็นไฟล์ PDF เดียวหน้าละ 1 คน (ไม่ใช้วิธีเดาการตัดหน้าอัตโนมัติของ
    html2pdf ที่เคยมีปัญหาหน้าเปล่า แต่วาดภาพแต่ละสลิปลงหน้าใหม่เองทีละหน้าแทน) เลือกคนเดียวจะพา
    ไปหน้าสลิปเดี่ยวแบบเดิมทุกประการ

## เฟส 3.6 — สลิปเงินเดือน (Manual) (เสร็จแล้ว ✅)
เมนู "สลิปเงินเดือน (Manual)": จัดทำสลิปเองสำหรับกรณีจ่ายเพิ่มเติม/ตกเบิก/ค่าตอบแทนพิเศษ
ที่ไม่ได้มาจากไฟล์ Excel ที่นำเข้าปกติ — กรอกชื่อผู้รับเงิน (มี autocomplete จากรายชื่อพนักงาน
แต่ไม่บังคับต้องมีในระบบ), หัวข้อ/เหตุผล, วันที่, รายการรับ-หักแบบเพิ่ม/ลบได้อิสระ, หมายเหตุ
ใช้สลิปหน้าตาเดียวกับสลิปที่มาจาก Excel (A4 + ลายน้ำ + พิมพ์ + PDF) เก็บแยกตาราง
`manual_slips` คนละตารางกับ `payroll_records` ไม่ปนกับข้อมูลที่นำเข้า

## เฟส 3.5 — ตั้งค่าหน่วยงาน (เสร็จแล้ว ✅)
เมนู "ตั้งค่า": แก้ไขชื่อ/ที่อยู่/เบอร์โทร/อีเมล/ผู้บริหาร + อัปโหลดโลโก้ (เก็บใน Supabase
Storage บักเก็ต `org-assets`) จำกัดแก้ไขได้เฉพาะ admin ข้อมูลนี้ใช้แสดงในแถบเมนูซ้าย/แถบบน
และในหัวกระดาษ+ลายน้ำของสลิปเงินเดือน

## เฟส 4 — รายงานและการจัดการ (เสร็จบางส่วน 🟡)
14. ดูรายงานเงินเดือน (สรุปยอดรวมตามกอง/เดือน/ปีงบประมาณ, กราฟ) — ยังไม่ได้ทำ
15. จัดการข้อมูลหน่วยงาน (เพิ่ม/แก้ไข/ปิดการใช้งานกอง-สำนัก แบบมีปุ่มในเว็บ) — ยังไม่ได้ทำ ตอนนี้ทำผ่าน SQL ได้
16. จัดการผู้ใช้งานและสิทธิ์ — **ทำแล้ว ✅** (เมนู "จัดการผู้ใช้งาน" เห็นเฉพาะ admin: ดูรายชื่อผู้ใช้
    ทั้งหมด เปลี่ยน role staff/admin และปิด/เปิดใช้งานบัญชีได้ บังคับด้วย RLS จริงที่ระดับฐานข้อมูล
    ไม่ใช่แค่ซ่อนปุ่ม บัญชีที่ถูกปิดจะเข้าอ่าน/เขียนข้อมูลอะไรไม่ได้อีกทันที ป้องกัน admin ลบ/ปิด
    สิทธิ์ตัวเองจนล็อกตัวเองออกจากระบบ — การสร้างบัญชีใหม่ยังต้องให้ผู้ใช้สมัครเองที่หน้าล็อกอิน
    ก่อน แล้ว admin มากำหนด role ทีหลัง เพราะสร้างบัญชีคนอื่นจากฝั่งเว็บโดยตรงต้องใช้ service_role
    key ซึ่งไม่ปลอดภัยที่จะฝังไว้ในโค้ดฝั่งเบราว์เซอร์ — เพิ่มปุ่ม "ลบ" ถาวรแล้ว สำหรับกรณีบุคคลนั้น
    ไม่ได้ทำงานที่นี่แล้ว (ต่างจาก "ปิดใช้งาน" ที่ยังเก็บบัญชีไว้ชั่วคราว) ลบบัญชีตัวเองไม่ได้ทั้งที่
    ปุ่มและที่ RLS ข้อมูลเก่าที่เคยทำไว้ (นำเข้า/สลิป/ตั้งค่า) ยังอยู่ครบ แค่ไม่ระบุชื่อผู้ทำรายการ
    อีกต่อไป — หมายเหตุ: ลบได้เฉพาะแถวโปรไฟล์ในระบบเท่านั้น บัญชีล็อกอิน (Supabase Auth) จริง ๆ
    ยังลบไม่ได้จากฝั่งเว็บด้วยเหตุผลเดียวกับข้างต้น แต่ไม่มีผลเพราะไม่มีโปรไฟล์แล้วจะเข้าถึงข้อมูล
    อะไรในระบบไม่ได้เลย (RLS บล็อกหมด) ถ้าพยายามล็อกอินจะถูกเด้งออกพร้อมข้อความแจ้งทันที)

## เฟส 4.5 — จำกัดสิทธิ์นำเข้า + โปรไฟล์ของฉัน (เสร็จแล้ว ✅)
- เมนู "นำเข้าข้อมูลเงินเดือน" เห็นได้เฉพาะ admin แล้ว (staff ไม่เห็นเมนูนี้อีกต่อไป)
- แก้ RLS ให้ตรงกับ UI จริง: การเขียนข้อมูล departments/employees/payroll_periods/
  payroll_records/import_logs/column_mapping_templates ทำได้เฉพาะ admin เท่านั้น (staff อ่านได้
  อย่างเดียว) กันไม่ให้ staff เรียก API ตรง ๆ ข้ามเมนูที่ซ่อนไว้ได้
- เมนูใหม่ "โปรไฟล์ของฉัน" เห็นได้ทั้ง admin และ staff: แก้ไขชื่อ-สกุลตัวเอง และเปลี่ยนรหัสผ่านได้เอง
- เพิ่ม trigger `prevent_self_role_escalation` กันไม่ให้ผู้ใช้เปลี่ยน role/active ของตัวเองผ่านช่องทางแก้ไขโปรไฟล์ (เปลี่ยนได้เฉพาะ admin ผ่านเมนู "จัดการผู้ใช้งาน" เท่านั้น)

## เฟส 5 — เตรียมใช้งานจริง (ยังไม่ได้ทำ ❌)
- ตั้งค่า GitHub Pages ให้ใช้งานได้จากอินเทอร์เน็ตจริง
- ปิดการสมัครสมาชิกแบบเปิดสาธารณะ (ให้แอดมินเชิญผู้ใช้แทน) — ปัจจุบันเปิด signup ไว้เพื่อทดสอบง่าย
- สำรองข้อมูล (Supabase มีระบบ backup อัตโนมัติในแผนเสียเงิน — ถ้าใช้แผนฟรีควร export ข้อมูลเป็นระยะ)
- ทดสอบกับผู้ใช้งานจริงและไฟล์ Excel เดือนอื่น ๆ (โครงสร้างอาจต่างจากไฟล์ตัวอย่างเล็กน้อย)
