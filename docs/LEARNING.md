# คู่มือเรียนรู้ระบบเงินเดือน (สำหรับคนที่ไม่เคยเขียนโปรแกรมมาก่อน)

เอกสารนี้อธิบายทุกอย่างที่สร้างไว้ในโปรเจกต์นี้ ตั้งแต่แนวคิดพื้นฐานไปจนถึงวิธีใช้งานจริง
อ่านตามลำดับหัวข้อได้เลย ไม่ต้องรีบ อ่านครั้งเดียวอาจไม่เข้าใจหมด แต่ทำตามไปเรื่อย ๆ จะเริ่มต่อจุดได้เอง

---

## 1. ภาพรวม: เว็บแอปหนึ่งตัวประกอบด้วยอะไรบ้าง

ระบบนี้แบ่งเป็น 3 ส่วนที่ทำงานร่วมกัน:

```
[เบราว์เซอร์ของผู้ใช้]  <--HTTPS-->  [เว็บไซต์ (Frontend)]  <--API-->  [ฐานข้อมูล Supabase]
        คุณ                     GitHub Pages เก็บไฟล์            เก็บข้อมูลจริงถาวร
                                 HTML/CSS/JS ให้เปิดดู            (พนักงาน, เงินเดือน, ผู้ใช้)
```

- **Frontend (หน้าเว็บ)** คือไฟล์ `.html` `.css` `.js` ในโฟลเดอร์นี้ — สิ่งที่ผู้ใช้ "เห็นและกดปุ่ม"
  ตัวมันเองไม่เก็บข้อมูลอะไรถาวร แค่แสดงผลกับรับคำสั่ง
- **ฐานข้อมูล (Database)** คือที่ที่ข้อมูลจริงถูกเก็บไว้ถาวร (เงินเดือนแต่ละคนแต่ละเดือน ฯลฯ)
  เราใช้บริการชื่อ **Supabase** ซึ่งให้ฐานข้อมูล Postgres ฟรีพร้อมระบบล็อกอินในตัว
- **GitHub** คือที่เก็บ "โค้ดต้นฉบับ" (source code) ทุกครั้งที่แก้โค้ดแล้ว push ขึ้น GitHub
  คือการ "บันทึกเวอร์ชัน" ของงาน ส่วน **GitHub Pages** คือฟีเจอร์ที่เอาไฟล์ในเว็บใน repo
  มาทำเป็นเว็บไซต์จริงที่มี URL ให้เปิดจากที่ไหนก็ได้

จำง่าย ๆ: **โค้ดอยู่ที่ GitHub → ข้อมูลอยู่ที่ Supabase → คนเปิดเว็บผ่าน GitHub Pages**

## 2. คำศัพท์ที่ต้องรู้ (แปลแบบง่าย)

| คำศัพท์ | ความหมายง่าย ๆ |
|---|---|
| HTML | โครงหน้าเว็บ (มีอะไรบ้าง ปุ่มอยู่ตรงไหน) |
| CSS | ความสวยงาม สี ระยะห่าง |
| JavaScript (JS) | ตรรกะ/พฤติกรรม เช่น กดปุ่มแล้วเกิดอะไรขึ้น |
| Git | โปรแกรมช่วย "บันทึกประวัติการแก้ไขโค้ด" ทีละจุด |
| Commit | การบันทึกประวัติ 1 ครั้ง พร้อมข้อความอธิบายว่าแก้อะไร |
| Push | การส่งประวัติที่บันทึกไว้ (commit) ขึ้นไปเก็บบน GitHub |
| Repository (repo) | "โฟลเดอร์โปรเจกต์" ที่ถูกเก็บประวัติด้วย Git |
| Branch | สาขาของโค้ด ใช้แยกงานที่กำลังทำจากงานหลักที่ใช้งานจริง |
| Database / Table | ฐานข้อมูล / ตารางข้อมูล (คล้ายชีท Excel แต่ทำงานร่วมกันหลายคนพร้อมกันได้ปลอดภัยกว่า) |
| API Key | "รหัสผ่าน" ที่หน้าเว็บใช้แนะนำตัวกับฐานข้อมูลว่า "ฉันมาจากเว็บนี้นะ" |
| RLS (Row Level Security) | กฎที่ตั้งไว้ในฐานข้อมูลว่า "ใครดู/แก้ไขข้อมูลแถวไหนได้บ้าง" — ต่อให้ API Key หลุดไปคนอื่นก็ยังเข้าไม่ได้ถ้าไม่ได้ล็อกอิน |
| Authentication (Auth) | ระบบล็อกอิน/ยืนยันตัวตน |
| JSON / JSONB | รูปแบบเก็บข้อมูลแบบยืดหยุ่น เช่น `{"เงินเดือน": 20000}` — ใช้เก็บรายการเงินเดือนที่คอลัมน์ไม่ตายตัว |

## 3. โครงสร้างไฟล์ในโปรเจกต์นี้

```
bank001/
├── index.html              หน้าเว็บหลัก (มีหน้าล็อกอิน + โครงแอปทั้งหมดอยู่ในไฟล์เดียว)
├── css/
│   └── style.css           สีสัน ธีมเขียว การ์ดสถิติ ตาราง ปุ่ม ฯลฯ
├── js/
│   ├── supabaseClient.js   ตั้งค่าการเชื่อมต่อฐานข้อมูล Supabase
│   ├── xlsx-parser.js      อ่านและตีความไฟล์ Excel เงินเดือน
│   ├── app.js               ระบบล็อกอิน, เมนู, แดชบอร์ด, ค้นหาพนักงาน, ประวัติการนำเข้า
│   └── import.js            ตัวช่วยนำเข้า Excel ทีละขั้นตอน (wizard 6 ขั้น)
├── supabase/
│   └── schema.sql           คำสั่งสร้างตารางฐานข้อมูลทั้งหมด (สำเนาไว้ดู/รันซ้ำได้)
└── docs/
    ├── LEARNING.md          ไฟล์นี้
    └── ROADMAP.md           แผนพัฒนาเฟสถัดไป
```

**ทำไมไม่มีไฟล์ `build`, `package.json`, หรือ framework อย่าง React?**
เพราะโปรเจกต์นี้ตั้งใจใช้ HTML/CSS/JavaScript "เปล่า ๆ" (vanilla) ไม่ผ่านการแปลงโค้ด (build step)
เปิดไฟล์ `.html` ในเบราว์เซอร์ได้เลย เหมาะกับการเริ่มเรียนรู้ที่สุด เมื่อคุ้นเคยแล้วค่อยพิจารณาใช้ React/Vue ทีหลังได้

## 4. ฐานข้อมูล Supabase ที่ตั้งไว้ให้แล้ว

โปรเจกต์นี้เชื่อมกับ Supabase project ชื่อ **"Nattara29's Project"** (อยู่ในบัญชี Supabase ของคุณ) ไว้แล้ว
ดูข้อมูลเชื่อมต่อ (URL/Key) ได้ในไฟล์ `js/supabaseClient.js` — ค่าพวกนี้ **เอาไปฝังในหน้าเว็บได้อย่างปลอดภัย**
เพราะความปลอดภัยจริง ๆ มาจาก **RLS** ที่ตั้งไว้ในฐานข้อมูล (ต้องล็อกอินก่อนถึงจะอ่าน/เขียนข้อมูลได้)

### ตารางที่สร้างไว้ (ดูรายละเอียดเต็มใน `supabase/schema.sql`)

| ตาราง | เก็บอะไร |
|---|---|
| `profiles` | ข้อมูลผู้ใช้งานระบบ (ชื่อ, สิทธิ์ admin/staff) |
| `departments` | รายชื่อกอง/สำนัก (นำเข้าจากไฟล์ Excel ตัวอย่างไว้ 8 กองแล้ว) |
| `employees` | บุคลากรแต่ละคน |
| `payroll_periods` | งวดเงินเดือน (เดือน/ปี หนึ่งงวด) |
| `payroll_records` | ยอดเงินเดือนของแต่ละคนในแต่ละงวด (เก็บรายการรับ-หักแบบยืดหยุ่นด้วย JSONB) |
| `column_mapping_templates` | แม่แบบการจับคู่คอลัมน์ Excel ไว้ใช้ซ้ำเดือนถัดไป |
| `import_logs` | ประวัติการนำเข้าไฟล์แต่ละครั้ง |

ถ้าต้องการดู/แก้ไขข้อมูลตรง ๆ (ไม่ผ่านหน้าเว็บ) เข้าไปที่ https://supabase.com/dashboard
เลือกโปรเจกต์ แล้วไปที่เมนู **Table Editor** หรือ **SQL Editor**

### ทำไมสมัครสมาชิกแล้วเป็น "เจ้าหน้าที่ (staff)" ไม่ใช่ "ผู้ดูแลระบบ (admin)"

ทุกบัญชีใหม่จะได้สิทธิ์ `staff` โดยอัตโนมัติ (ปลอดภัยไว้ก่อน) ถ้าต้องการตั้งให้ใครเป็น admin
ตอนนี้ต้องทำผ่าน SQL Editor ชั่วคราว (ยังไม่มีหน้าจัดการผู้ใช้ในเว็บ — อยู่ในเฟส 4 ตาม ROADMAP.md):

```sql
update public.profiles set role = 'admin' where full_name = 'ชื่อที่สมัครไว้';
```

## 5. ทำความเข้าใจ flow การนำเข้า Excel (หัวใจของระบบ)

ไฟล์ Excel ตัวอย่างที่ใช้ออกแบบระบบนี้ (`PD_SalaryDoc4Mtx_Excel_1.xlsx`) มีโครงสร้างพิเศษ:
**หนึ่งชีท = หนึ่งกอง/สำนัก** และหัวตารางมี 2 ชั้น (กลุ่มใหญ่ เช่น "รายการรับ"/"รายการหัก"
แล้วมีหัวย่อยใต้กลุ่มนั้นอีกที เช่น "เงินเดือน", "ภาษีหัก ณ ที่จ่าย")

ปัญหาคือ **คอลัมน์การหักเงินไม่เท่ากันทุกเดือน** (บางเดือนมีคนหักสหกรณ์ บางเดือนไม่มี ฯลฯ)
ระบบเลยต้องมีขั้นตอน "Mapping" ให้ผู้ใช้ยืนยันว่าคอลัมน์ไหนคือรายการรับ/หัก ก่อนบันทึกจริง

### ขั้นตอนทั้ง 6 ในหน้า "นำเข้าข้อมูลเงินเดือน" (`js/import.js`)

1. **อัปโหลด** — เลือกไฟล์ + ระบุปี/เดือนของงวด ไฟล์จะถูกอ่านทันทีด้วยไลบรารี `xlsx` (SheetJS)
2. **ตรวจสอบโครงสร้าง** — `js/xlsx-parser.js` จะไล่หาแถวหัวตาราง (แถวที่มีคำว่า "ชื่อ" และ
   "ประเภทพนักงาน") ในทุกชีท แล้วรายงานว่าชีทไหนอ่านได้/อ่านไม่ได้
3. **Mapping คอลัมน์** — ระบบเดาให้อัตโนมัติว่าคอลัมน์ไหนเป็นรายการรับ/หัก/ยอดสุทธิ (ดูจากหัวตาราง)
   ผู้ใช้ตรวจสอบ/แก้ไขได้ก่อนไปต่อ และสามารถบันทึกเป็น "แม่แบบ" ไว้ใช้ซ้ำเดือนถัดไป
4. **ตรวจสอบข้อมูล** — ระบบตรวจ 4 อย่างอัตโนมัติ:
   - มีชื่อ-สกุลและประเภทพนักงานครบไหม
   - ยอดรวมรายการรับที่คำนวณเอง ตรงกับคอลัมน์ "รวมรายการรับ" ในไฟล์ไหม
   - ยอดรวมรายการหักที่คำนวณเอง ตรงกับคอลัมน์ "รวมรายการหัก" ในไฟล์ไหม
   - ยอดรับสุทธิที่คำนวณเอง (รับ-หัก) ตรงกับคอลัมน์ "รับสุทธิ" ในไฟล์ไหม
   - แถวไหนมีปัญหาจะ **ไม่ถูกนำเข้า** (กันข้อมูลผิดหลุดเข้าระบบ) แต่แถวที่ถูกต้องนำเข้าได้ตามปกติ
5. **Preview** — แสดงตารางสรุปทุกคนที่จะถูกบันทึกจริง ให้ตรวจทานครั้งสุดท้าย
6. **ยืนยันนำเข้า** — กดแล้วระบบจะ:
   - สร้างงวดเงินเดือน (ถ้ายังไม่มี)
   - สร้างกอง/สำนักที่ยังไม่มีในระบบ (เผื่อชื่อชีทใหม่)
   - สร้างพนักงานใหม่ที่ยังไม่เคยมีในระบบ (จับคู่ด้วยชื่อ+กอง)
   - บันทึก/อัปเดตยอดเงินเดือนของทุกคนในงวดนั้น
   - บันทึกประวัติการนำเข้า (ดูย้อนหลังได้ที่เมนู "ประวัติการนำเข้า")

> ทดสอบแล้วกับไฟล์ตัวอย่างจริง: อ่านได้ครบทั้ง 8 ชีท รวม 148 รายการ และยอดรวมทุกแถวตรงกับ
> ที่ไฟล์ Excel คำนวณไว้เป๊ะ (ไม่มี error แม้แต่แถวเดียว)

## 6. วิธีทดสอบระบบบนเครื่องตัวเอง (ก่อนขึ้นเว็บจริง)

วิธีง่ายที่สุด: ดับเบิลคลิกไฟล์ `index.html` เปิดในเบราว์เซอร์ได้เลย
ถ้าเจอปัญหาเรื่องโหลดข้อมูลไม่ขึ้น แนะนำใช้ตัวช่วยรันเซิร์ฟเวอร์เล็ก ๆ แทน:

- ถ้ามี VS Code: ติดตั้งส่วนขยาย **Live Server** แล้วคลิกขวาที่ `index.html` เลือก "Open with Live Server"
- หรือถ้ามี Python: เปิด terminal ในโฟลเดอร์นี้แล้วพิมพ์ `python3 -m http.server 8000`
  แล้วเปิดเบราว์เซอร์ไปที่ `http://localhost:8000`

ครั้งแรกที่เปิด ต้อง **สมัครสมาชิก** ก่อน (กดลิงก์ "สมัครใช้งาน" ที่หน้าล็อกอิน)
ใช้อีเมลจริงของคุณได้เลย (ระบบยังไม่บังคับยืนยันอีเมลในตอนนี้ เพื่อทดสอบง่าย)

## 7. วิธีเอาขึ้น GitHub Pages ให้ใช้งานจริงได้

1. เข้า repo บน GitHub → แท็บ **Settings** → เมนูซ้าย **Pages**
2. หัวข้อ "Build and deployment" → Source เลือก **Deploy from a branch**
3. Branch เลือกสาขาที่ต้องการเผยแพร่ (เช่น `main`) และโฟลเดอร์เลือก **/ (root)**
4. กด **Save** รอสักครู่ GitHub จะให้ลิงก์เว็บไซต์ เช่น
   `https://<ชื่อบัญชี>.github.io/bank001/`
5. เข้าลิงก์นั้นได้จากที่ไหนก็ได้ — นี่คือเว็บที่ใช้งานจริง

**ข้อควรระวัง:** งานที่ทำในเซสชันนี้อยู่บนสาขา `claude/sawasdee-krap-ozd667`
ถ้าต้องการให้เว็บจริงใช้โค้ดล่าสุด ต้องรวม (merge) สาขานี้เข้ากับสาขาหลักก่อน (เช่นผ่าน Pull Request)

## 8. สิ่งที่ยังไม่ได้ทำ (ดูรายละเอียดที่ `docs/ROADMAP.md`)

ระบบตอนนี้ครอบคลุมตั้งแต่ **อัปโหลด Excel → mapping → validate → preview → บันทึกเงินเดือน**
รวมถึงค้นหาพนักงานและดูประวัติการนำเข้าเบื้องต้นแล้ว

ที่ยังไม่ได้ทำ (ตั้งใจแบ่งไว้เป็นเฟสถัดไป เพื่อไม่ให้ทดสอบพร้อมกันเยอะเกินไป):
- หน้าสร้าง/พิมพ์/Export PDF สลิปเงินเดือน (รายคนและหลายคน)
- หน้ารายงานสรุปเงินเดือนเชิงลึก (กราฟ, แยกตามกอง/ปีงบประมาณ)
- หน้าจัดการหน่วยงาน (เพิ่ม/แก้ไข/ปิดกอง-สำนัก) แบบมีปุ่มในเว็บ (ตอนนี้ทำผ่าน SQL ได้)
- หน้าจัดการผู้ใช้งานและสิทธิ์ (ตั้ง role แอดมิน/พนักงาน)

บอกได้เลยว่าอยากให้ทำเฟสไหนต่อ จะอธิบายและสร้างให้ทีละเฟสเหมือนเดิม

## 9. แก้ปัญหาที่พบบ่อย (Troubleshooting)

- **หน้าเว็บขึ้นแต่ปุ่ม/ล็อกอินไม่ทำงานเลย** — เปิด Developer Tools (กด F12) แท็บ Console
  ถ้าเห็นข้อความแดงว่า `supabase is not defined` แปลว่าไลบรารีจาก CDN โหลดไม่สำเร็จ
  มักเกิดจากเครือข่ายองค์กร/ไฟร์วอลล์บล็อก `cdn.jsdelivr.net` หรือ `cdnjs.cloudflare.com` —
  ลองเปิดจากเครือข่ายอื่น หรือแจ้งฝ่าย IT ให้ปลดบล็อกโดเมนทั้งสองนี้
- **"Invalid login credentials"** — สมัครสมาชิกใหม่ก่อน (ยังไม่มีบัญชีไหนอยู่ในระบบเลยตอนเริ่มต้น)
- **นำเข้า Excel แล้วบอกว่า "ไม่พบแถวหัวตาราง"** — ไฟล์ชีทนั้นต้องมีคำว่า "ชื่อ" และ
  "ประเภทพนักงาน" อยู่ในแถวเดียวกัน ถ้าไฟล์เดือนอื่นใช้คำเรียกต่างไป แจ้งมาได้ จะปรับให้รองรับเพิ่ม
- **ยอดรวมไม่ตรง (มี error สีแดงตอนตรวจสอบข้อมูล)** — มักเกิดจาก mapping คอลัมน์ผิด
  (เช่น ไปทำเครื่องหมายคอลัมน์ "รวมรายการรับ" เป็นรายการย่อยด้วย) ลองย้อนกลับไปขั้นตอน Mapping ใหม่
